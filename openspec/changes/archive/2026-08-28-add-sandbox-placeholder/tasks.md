## 1. Wildcard-сертификат

- [x] 1.1 Выпустить сертификат `*.zerotomvp.xyz` через DNS-01 у Cloudflare токеном из `CLOUDFLARE_DNS_API_TOKEN`; проверка — `openssl x509` показывает SAN с wildcard и валидный срок
- [x] 1.2 Настроить автоматическое продление на сервере с проверкой не реже раза в сутки; проверка — принудительный прогон в тестовом режиме проходит без участия человека
- [x] 1.3 Обеспечить подхват обновлённого сертификата прокси без ручного перезапуска; проверка — после замены файлов сертификата прокси отдаёт новый (спека `platform-deployment`)

## 2. Перехватчик в прокси

- [x] 2.1 Поднять маршрут-перехватчик с пустым хостом и wildcard-сертификатом; проверка — произвольное имя в зоне устанавливает TLS с валидным сертификатом (спека `sandbox-address`)
- [x] 2.2 Убедиться, что точные маршруты выигрывают у перехватчика; проверка — апекс, `registry`, `app` и `staging` продолжают отвечать своим содержимым

## 3. Страница состояния

- [x] 3.1 Определять сэндбокс по заголовку Host и читать его состояние из реестра имён; проверка — тесты на известное имя, неизвестное имя и имя вне зоны платформы
- [x] 3.2 Определять наличие образа в реестре образов, отличая «образа нет» от «реестр недоступен»; проверка — тесты на оба случая, во втором странице сообщается о неизвестном состоянии
- [x] 3.3 Собрать страницу состояния в том же оформлении, что и остальные; проверка — три состояния открываются и читаются, ссылка на репозиторий ведёт куда надо (спека `sandbox-address`)
- [x] 3.4 Проверить, что страница ничего не раскрывает: ни путей к образам, ни внутренних идентификаторов; проверка — тест на состав ответа

## 4. Страница результата

- [x] 4.1 Показывать на странице результата текущее состояние сэндбокса вместо одного лишь обещания адреса; проверка — сразу после создания видно, что сборка ещё не проходила

## 5. Приёмка

- [x] 5.1 Открыть в браузере адрес существующего несозданного, созданного без образа и созданного с образом сэндбокса; проверка — во всех трёх случаях нет предупреждения браузера и текст соответствует состоянию
- [x] 5.2 Проверить, что соседний проект и реестр не задеты; проверка — `app`, `staging` и `registry` отвечают как раньше
