## Purpose

Платформа должна быть доступна по публичному адресу с валидным TLS: без этого невозможен ни callback GitHub OAuth, ни проверка сквозного сценария создания сэндбокса. Эта возможность описывает наблюдаемые требования к доставке и к домену.

## ADDED Requirements

### Requirement: Платформа доступна по публичному адресу с TLS

Платформа SHALL быть доступна по своему основному домену по HTTPS с валидным сертификатом. Обращения по HTTP SHALL перенаправляться на HTTPS.

#### Scenario: Открытие лендинга извне

- **WHEN** пользователь открывает основной домен платформы из интернета
- **THEN** соединение устанавливается по HTTPS с валидным сертификатом
- **AND** запрос по HTTP перенаправляется на HTTPS

#### Scenario: Callback GitHub OAuth

- **WHEN** GitHub возвращает пользователя на callback платформы
- **THEN** callback обслуживается по тому же публичному HTTPS-адресу, который зарегистрирован в OAuth App

### Requirement: Поддомены сэндбоксов ведут на платформу

DNS-зона основного домена SHALL быть настроена так, чтобы произвольный поддомен третьего уровня разрешался на инфраструктуру платформы. Это требуется заранее, до появления запуска сэндбоксов, чтобы адрес, обещанный пользователю при создании, не зависел от последующих изменений DNS.

#### Scenario: Разрешение имени незапущенного сэндбокса

- **WHEN** выполняется DNS-запрос для `<sandbox-name>.zerotomvp.xyz`
- **THEN** имя разрешается на инфраструктуру платформы
- **AND** отсутствие запущенного сэндбокса проявляется как ответ платформы, а не как ошибка DNS

### Requirement: Воспроизводимая доставка образом

Платформа SHALL разворачиваться из собранного образа, однозначно связанного с коммитом, а не из исходников на сервере. Развёртывание SHALL быть повторяемым одной командой и SHALL позволять вернуться на предыдущий образ.

#### Scenario: Развёртывание новой версии

- **WHEN** выполняется развёртывание платформы
- **THEN** на сервере запускается образ, соответствующий конкретному коммиту
- **AND** предыдущая версия остаётся доступной для отката

### Requirement: Конфигурация и секреты вне репозитория

Все учётные данные платформы — реквизиты OAuth App, строка подключения к базе, ключ подписи сессий — SHALL передаваться приложению через окружение и MUST NOT храниться в репозитории. Приложение SHALL отказываться стартовать, если обязательная переменная окружения отсутствует.

#### Scenario: Запуск без обязательной переменной

- **WHEN** приложение запускается без одной из обязательных переменных окружения
- **THEN** запуск завершается ошибкой с явным указанием, какой переменной не хватает
- **AND** приложение не начинает обслуживать запросы в частично сконфигурированном виде

### Requirement: Проверка работоспособности платформы

Платформа SHALL предоставлять endpoint проверки работоспособности, отвечающий успешным статусом только когда приложение готово обслуживать запросы, включая доступность базы данных.

#### Scenario: База недоступна

- **WHEN** база данных недоступна
- **THEN** endpoint проверки работоспособности не возвращает успешный статус
