## Purpose

Публичная точка входа в zerotomvp: объясняет, что даёт платформа, и предоставляет единственное действие — создать сэндбокс через GitHub. Также описывает страницу результата, на которой пользователь получает ссылки на свой репозиторий и будущий адрес сэндбокса.

## ADDED Requirements

### Requirement: Лендинг с единственным действием

Корневая страница платформы SHALL быть доступна анонимно и SHALL предлагать ровно одно основное действие — создание сэндбокса через GitHub. Страница SHALL сообщать до начала авторизации, что будет создан публичный репозиторий в аккаунте пользователя.

#### Scenario: Анонимный посетитель открывает лендинг

- **WHEN** анонимный пользователь открывает корневой адрес платформы
- **THEN** страница отдаётся без авторизации и содержит кнопку создания сэндбокса через GitHub
- **AND** рядом с кнопкой указано, что в аккаунте пользователя будет создан публичный репозиторий

#### Scenario: Пользователь запускает создание сэндбокса

- **WHEN** пользователь нажимает кнопку создания сэндбокса
- **THEN** браузер перенаправляется на авторизацию GitHub
- **AND** пользователю не требуется вводить имя сэндбокса или какие-либо другие данные

### Requirement: Страница результата

После успешного создания сэндбокса платформа SHALL показать страницу результата, содержащую имя сэндбокса, ссылку на созданный репозиторий и адрес поддомена, закреплённого за сэндбоксом. Страница SHALL явно сообщать, что сэндбокс ещё не запущен.

#### Scenario: Сэндбокс создан

- **WHEN** репозиторий пользователя успешно создан
- **THEN** отображается имя сэндбокса, ссылка на репозиторий на GitHub и адрес `<sandbox-name>.zerotomvp.xyz`
- **AND** указано, что адрес начнёт отвечать только после того, как сэндбокс будет запущен платформой

### Requirement: Понятные ошибки на лендинге

Любой сбой в процессе создания сэндбокса SHALL приводить к странице с человекочитаемым объяснением и возможностью повторить попытку. Платформа MUST NOT показывать пользователю сырые ответы GitHub API, трассировки или внутренние идентификаторы.

#### Scenario: Пользователь отказал в авторизации

- **WHEN** пользователь отклоняет запрос доступа на стороне GitHub
- **THEN** платформа показывает страницу с сообщением, что без доступа к GitHub сэндбокс создать нельзя
- **AND** предлагает повторить попытку

#### Scenario: Сбой на стороне GitHub

- **WHEN** обращение к GitHub API завершается ошибкой, которую нельзя устранить повтором с другим именем
- **THEN** платформа показывает сообщение о временной недоступности GitHub и предлагает повторить попытку позже
- **AND** сырой ответ GitHub API пользователю не показывается
