## Why

Платформы zerotomvp пока нет: репозиторий пуст, домен куплен, но входа в продукт не существует. Первый осмысленный срез — превратить посетителя в владельца сэндбокса: лендинг, вход через GitHub, созданный из шаблона репозиторий в его аккаунте и закреплённое за ним имя поддомена.

Этот change сознательно не включает сам хостинг прототипа, но фиксирует три вещи, которые дороже менять потом: контракт шаблона сэндбокса (Docker-образ), способ сборки образа (GitHub Actions в репозитории пользователя) и правила именования, от которых зависит DNS.

## What Changes

- Заводится второй наш репозиторий `gutnikov/sandbox-template`: Hono + React + Vite + shadcn, `Dockerfile`, `/healthz`, чтение `PORT` из окружения, workflow сборки образа в GHCR. Репозиторий публичный, с флагом Template.
- Появляется приложение zerotomvp: лендинг с единственным действием «создать сэндбокс», серверные роуты OAuth, страница результата.
- Вводится GitHub OAuth App (отдельные приложения для dev и prod) со скоупом `public_repo`. Токен пользователя используется в рамках одного запроса и не сохраняется.
- Вводится реестр имён сэндбоксов в Neon: имя резервируется на нашей стороне до обращения к GitHub, потому что имя — это глобальный поддомен, а не запись внутри аккаунта пользователя.
- Имена генерируются автоматически в формате `sandbox-<adjective>-<noun>`; обязательный префикс `sandbox-` структурно исключает захват наших собственных поддоменов (`www`, `api`, `app`).
- Настраивается доставка: `Dockerfile` приложения, `config/deploy.yml` для Kamal, образ в GHCR, деплой на VPS, DNS на апекс и wildcard, TLS через kamal-proxy. Без публичного URL OAuth callback непроверяем, поэтому деплой входит в скоуп.

## Capabilities

### New Capabilities

- `landing`: публичная страница входа в продукт и страница результата создания сэндбокса.
- `auth/github-oauth`: вход через GitHub, обмен кода на токен, защита от CSRF, правила обращения с токеном и сессионной кукой.
- `sandbox-naming`: генерация, формат и резервирование имени сэндбокса как глобального идентификатора и поддомена.
- `sandbox-provisioning`: создание репозитория пользователя из шаблона и связывание его с зарезервированным именем.
- `sandbox-template`: требования к содержимому шаблона — контракт, по которому платформа позже сможет собрать и запустить прототип.
- `platform-deployment`: сборка и доставка самой платформы на VPS, домены и TLS.

### Modified Capabilities

Нет: в проекте пока нет ни одной существующей спеки.

## Impact

- Новый код: всё приложение с нуля (Hono, React, TanStack, Vite, shadcn, TypeScript).
- Новый репозиторий: `gutnikov/sandbox-template`.
- Внешние системы: GitHub OAuth Apps (dev + prod), GitHub REST API (`POST /repos/{owner}/{repo}/generate`), GHCR, Neon, DNS зоны `zerotomvp.xyz`, VPS.
- Секреты: `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `DATABASE_URL`, `SESSION_SECRET` — через Kamal secrets.
- Отложено намеренно: приём вебхука о собранном образе, запуск контейнеров сэндбоксов, роутинг `*.zerotomvp.xyz`, список «мои сэндбоксы».
