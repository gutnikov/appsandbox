## Context

Мотивация — см. `proposal.md`. Здесь только то, что определяет способ.

Ключевой факт, установленный на живом сэндбоксе: kamal-proxy отвечает `TLS handshake error: unknown server name` для хоста, у которого нет сервиса. Отказ происходит до разбора HTTP-запроса, поэтому ни страницы ошибки, ни редиректа отдать нельзя — сначала нужен сертификат.

На сервере уже работает общий kamal-proxy, через который ходят соседний проект и наш реестр. Всё, что мы делаем, обязано быть к нему добавлением, а не заменой.

## Goals / Non-Goals

**Goals:**
- Ни один адрес в зоне не приводит к предупреждению браузера.
- Основание для будущих сэндбоксов: сертификат, который не упирается в лимиты при росте числа сэндбоксов.

**Non-Goals:**
- Запуск контейнеров сэндбоксов и всё, что с ним связано.
- Прогресс сборки в реальном времени: страница показывает состояние на момент запроса, без подписки на события.

## Decisions

### Wildcard-сертификат, а не сертификат на каждый сэндбокс

Let's Encrypt выдаёт wildcard только по DNS-01, поэтому нужен доступ к зоне. Альтернатива — HTTP-01 на каждое имя по мере появления — отпадает по двум причинам: лимит 50 сертификатов в неделю на зарегистрированный домен, и то, что имя должно отвечать по HTTPS ещё до первого запуска сэндбокса.

Токен Cloudflare ограничен правом правки DNS одной зоны. Хранится как секрет окружения, в репозиторий не попадает.

### Продление отдельным процессом, а не частью платформы

Продление — задача инфраструктуры, а не приложения: сертификат нужен прокси, даже когда платформа не выкачена. Поэтому это периодическая задача на сервере рядом с прокси, а не код внутри Hono.

### Перехватчик как обычный сервис прокси с пустым хостом

kamal-proxy трактует пустой `--host` как перехватчик и отдаёт ему всё, для чего нет точного совпадения. Точные маршруты — апекс, реестр, соседний проект, а позже и каждый запущенный сэндбокс — продолжают выигрывать. Это даёт нужный приоритет без единой строки конфигурации на каждое имя.

### Страницу состояния отдаёт сама платформа

Отдельный сервис-заглушка не нужен: платформа уже знает реестр имён, а состояние образа читается из нашего же реестра образов. Обработчик определяет сэндбокс по заголовку Host.

Плата: пока платформа не выкачена, поддомены отвечают ошибкой прокси. Это приемлемо — окно короткое, и оно не хуже нынешнего постоянного состояния.

## Risks / Trade-offs

- **Токен правки DNS на сервере** → компрометация сервера даёт власть над зоной. Смягчение: право только на DNS одной зоны, никаких других разрешений; при желании — ограничение по IP сервера.
- **Просроченное продление ломает сразу все поддомена** → в отличие от сертификата на имя, здесь единая точка отказа. Смягчение: продление сильно заранее и проверка срока в мониторинге.
- **Перехватчик может перехватить лишнее**, если у сервиса пропадёт точный маршрут → посетитель увидит страницу «сэндбокса нет» вместо приложения. Смягчение: проверка после выката, что апекс, реестр и соседний проект отвечают своим.
- **Страница врёт о состоянии, если реестр образов недоступен** → лучше сказать «не знаем», чем «образа нет». Обработчик должен различать эти случаи.

## Migration Plan

Порядок: выпуск сертификата → проверка, что он покрывает произвольное имя → перехватчик в прокси → выкат платформы с обработчиком. Откат — снять перехватчик из прокси, вернётся нынешнее поведение.
