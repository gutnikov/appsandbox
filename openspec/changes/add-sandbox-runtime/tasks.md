- [x] 2.3 Реализовать чтение фактического и желаемого состояния одним запросом; проверка — тесты на все переходы

## 3. Процесс сведения состояний

- [ ] 3.1 Написать процесс, который читает желаемое состояние и приводит к нему фактическое; проверка — на пробном сэндбоксе контейнер поднимается и регистрируется маршрут
- [ ] 3.2 Задать пределы памяти и процессора, запретить повышение привилегий; проверка — контейнер с заведомой утечкой останавливается один, платформа продолжает отвечать (спека `sandbox-runtime`)
- [ ] 3.3 Реализовать остановку по истечении времени жизни; проверка — сэндбокс останавливается, память освобождается
- [ ] 3.4 Реализовать предел одновременно запущенных с вытеснением по давности; проверка — при исчерпании предела вытесняется самый давний, запрошенный поднимается
- [ ] 3.5 Реализовать сведение расхождений: исчезнувший контейнер, осиротевший маршрут, состояние после перезагрузки; проверка — принудительное удаление контейнера восстанавливается без вмешательства
- [ ] 3.6 Оформить процесс как службу с автозапуском; проверка — после перезагрузки сервера адреса сэндбоксов отвечают

## 7. Приёмка

- [ ] 7.1 Сквозной прогон: push в существующий сэндбокс → открытие его адреса → работающий прототип; проверка — виден сам прототип, а не страница платформы
- [ ] 7.2 Прогон вытеснения: поднять больше сэндбоксов, чем предел; проверка — все адреса продолжают работать, память в границах
- [ ] 7.3 Проверить изоляцию из работающего сэндбокса; проверка — из него недоступны база, реестр и управление контейнерами
- [ ] 7.4 Перезагрузить сервер; проверка — без вмешательства адреса сэндбоксов, апекс и реестр отвечают
