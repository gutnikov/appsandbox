# sandbox-naming Specification

## Purpose
Имя сэндбокса — одновременно название репозитория пользователя и поддомен третьего уровня в зоне `zerotomvp.xyz`. Эта возможность задаёт формат имени, способ его генерации и правило резервирования, гарантирующее, что обещанный пользователю адрес действительно за ним закреплён.

## Requirements

### Requirement: Формат имени сэндбокса

Имя сэндбокса SHALL начинаться с префикса `sandbox-`, состоять только из строчных латинских букв, цифр и дефисов, и SHALL быть корректной меткой DNS длиной не более 63 символов. Имя SHALL генерироваться платформой автоматически; пользователь его не задаёт.

#### Scenario: Сгенерированное имя

- **WHEN** платформа генерирует имя для нового сэндбокса
- **THEN** имя имеет вид `sandbox-<слово>-<слово>` из строчных букв и дефисов
- **AND** имя пригодно и как название репозитория GitHub, и как метка DNS

#### Scenario: Префикс защищает служебные поддомены

- **WHEN** платформа генерирует любое имя сэндбокса
- **THEN** имя не может совпасть со служебным поддоменом платформы, таким как `www`, `api`, `app` или `mail`
- **AND** отдельный список запрещённых имён для этого не требуется

### Requirement: Имя глобально уникально и резервируется до обращения к GitHub

Имя сэндбокса SHALL быть уникальным в пределах всей платформы, поскольку соответствует глобальному поддомену. Платформа SHALL зафиксировать имя в собственном реестре до создания репозитория на GitHub и SHALL гарантировать уникальность на уровне хранилища, а не только проверкой перед записью.

#### Scenario: Одновременные запросы на создание

- **WHEN** два запроса на создание сэндбокса одновременно получают одно и то же сгенерированное имя
- **THEN** реестр принимает только одно из них
- **AND** второй запрос получает другое имя и продолжает работу

#### Scenario: Имя занято в реестре

- **WHEN** сгенерированное имя уже присутствует в реестре платформы
- **THEN** платформа генерирует новое имя и повторяет попытку
- **AND** число попыток ограничено, после чего пользователю показывается ошибка

### Requirement: Освобождение имени при неудачном создании

Если репозиторий на GitHub создать не удалось, платформа SHALL освободить зарезервированное имя, чтобы оно снова стало доступным. Реестр MUST NOT содержать имён, за которыми не стоит существующий репозиторий пользователя.

#### Scenario: GitHub отклонил создание репозитория

- **WHEN** имя зарезервировано, но создание репозитория на GitHub завершилось ошибкой
- **THEN** резерв этого имени снимается
- **AND** имя может быть выдано другому сэндбоксу

### Requirement: Запись о сэндбоксе

Для каждого успешно созданного сэндбокса реестр SHALL хранить его имя, логин владельца на GitHub, адрес созданного репозитория и момент создания. Реестр MUST NOT хранить токен доступа пользователя.

#### Scenario: Успешное создание сэндбокса

- **WHEN** репозиторий пользователя создан
- **THEN** запись в реестре содержит имя, логин владельца, ссылку на репозиторий и время создания
- **AND** запись не содержит учётных данных или токенов
