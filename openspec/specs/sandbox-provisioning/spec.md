# sandbox-provisioning Specification

## Purpose
Создание сэндбокса как наблюдаемого результата: в аккаунте пользователя появляется публичный репозиторий, порождённый из шаблона платформы и связанный с зарезервированным за ним именем и поддоменом.

## Requirements

### Requirement: Репозиторий создаётся из шаблона в личном аккаунте пользователя

Платформа SHALL создавать репозиторий сэндбокса из шаблонного репозитория платформы в личном аккаунте авторизовавшегося пользователя. Репозиторий SHALL быть публичным. Платформа MUST NOT создавать репозиторий в организации и MUST NOT предлагать выбор владельца.

#### Scenario: Успешное создание

- **WHEN** пользователь авторизовался и имя сэндбокса зарезервировано
- **THEN** в личном аккаунте пользователя создаётся публичный репозиторий с этим именем
- **AND** содержимое репозитория соответствует шаблонному репозиторию платформы
- **AND** владельцем репозитория является пользователь, а не платформа

#### Scenario: Имя уже занято в аккаунте пользователя

- **WHEN** GitHub отклоняет создание, потому что репозиторий с таким именем у пользователя уже есть
- **THEN** платформа освобождает имя, генерирует новое и повторяет создание
- **AND** пользователь не видит промежуточной ошибки, если повтор оказался успешным

### Requirement: Один проход авторизации на один сэндбокс

Создание сэндбокса SHALL завершаться в рамках того же цикла авторизации, в котором пользователь дал доступ. Платформа MUST NOT требовать от пользователя дополнительных действий между авторизацией и получением готового репозитория.

#### Scenario: Возврат из GitHub

- **WHEN** пользователь возвращается из GitHub с успешной авторизацией
- **THEN** платформа сама генерирует имя, резервирует его и создаёт репозиторий
- **AND** пользователь попадает на страницу результата без промежуточных подтверждений

### Requirement: Идентификация сэндбокса и его адреса

Каждый созданный сэндбокс SHALL быть однозначно связан со своим именем, репозиторием на GitHub и адресом `<sandbox-name>.zerotomvp.xyz`. Платформа SHALL сообщать пользователю этот адрес при создании, даже если сэндбокс ещё не запущен.

#### Scenario: Адрес сообщается сразу

- **WHEN** сэндбокс создан
- **THEN** пользователю сообщается адрес его сэндбокса на поддомене `zerotomvp.xyz`
- **AND** сообщается, что адрес станет рабочим после запуска сэндбокса платформой

### Requirement: Границы этого этапа

Платформа на этом этапе SHALL ограничиваться созданием репозитория. Платформа MUST NOT создавать вебхуки, записывать секреты, изменять настройки репозитория пользователя после создания и MUST NOT собирать или запускать образ сэндбокса.

#### Scenario: После создания репозитория

- **WHEN** репозиторий сэндбокса создан
- **THEN** платформа больше не обращается к GitHub от имени пользователя
- **AND** в репозитории пользователя не появляется вебхуков и секретов, добавленных платформой
